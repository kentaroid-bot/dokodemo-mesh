# どこでもメッシュ · Dokodemo-Mesh

**2つ以上のどこでもデスクを繋ぐ中庭 ――「どこでもデスク」から「どこまでもデスク」へ**

それぞれの仕事場で育てた問いや知識を持ち寄り、一緒に考え、成果を持ち帰る。どこでもメッシュは、そのための小さな中庭です。

中身はフォルダとMarkdown数枚。人間やAIが読み、書き、続きを渡します。自分のデスク同士でも、他の人のデスクとも、同じ形で始められます。

```text
デスク A ←→ 中庭 ←→ デスク B
              ↕
           デスク C
```

**中庭は、各デスクの成果物と理解を豊かにするためにあります。**
主役は現場・作品・思考体としての各デスク。中庭の維持や拡大を目的にせず、必要な間だけ使い、用件が終われば持ち帰って解散する。城よりも、キャンプの焚き火に近い場所です。

## メッシュを名乗るための4つの条件

**デスクがメッシュのふりをすると、集権化が起きる。**
特定の誰かの判断に従わせる場所を、中立な広場とは呼ばない。このプロトコルでは、次の4条件を満たす場だけをメッシュとして扱います。

| 成立要件 | この中庭で守ること |
|---|---|
| **非私有性** | 特定のデスクをオーナーにしない。すべての参加者に対して中立で、管理を担うことが支配する権利にならない |
| **非蓄積性** | 成果や知見を囲い込まない。共同作業のために置き、各デスクへ持ち帰れる形にする |
| **全員合意** | 共通ルールを一方的に変えない。参加デスク全員が同じ変更案へ明示的に合意してから改訂する |
| **完全な解消可能性** | 各デスクはいつでも抜けられる。必要な成果を持ち帰り、中庭への依存を終えて解散できる |

満たさない場は、メッシュの接続先に含めません。誰かが管理するデスクとして扱い、協働するなら、その相手とのあいだに4条件を満たす中庭を開きます。

非蓄積性は「記録しない」という意味ではありません。作業中の問い、返答、判断理由は残します。その記録を中庭だけの資産にせず、持ち帰りと終了に結び付けます。

## 接続の3つの規則

| 接続 | 規則 |
|---|---|
| **Desk ↮ Desk** | このプロトコルでのデスク間のやり取りは、直接繋がない。相手の内部を訪ねて読んだり、書き換えたりする経路にしない |
| **Desk ↔ Mesh** | 外とのやり取りは必ず中庭を通す。共有すると決めた静的データを置き、自分のデスクへ持ち帰って考える |
| **Mesh ↔ Mesh** | 中庭同士も繋がる。そのあいだに、同じ条件・同じ形式の中庭をもう一つ置く |

```text
デスク A ←→ 中庭 α ←→ デスク B
               ↕
             中庭 γ
               ↕
デスク C ←→ 中庭 β ←→ デスク D
```

γでは、αとβが参加する窓口になります。どの中庭にも同じ4条件が適用され、γの合意がα・βの内部へ自動的に及ぶことはありません。フォルダの大小や置き場所が、権利の強弱を決めることもありません。

これが、対等な接続（P2P）と、同じ形を繰り返せる構造（フラクタル）です。上位の支配者を作らず、「どこでもデスク」から「どこまでもデスク」へ広げていきます。

## 内側は守り、開口部で繋がる

原本は各デスクに置いたまま、共同の仕事に必要な要約・抜粋・提案を中庭へ持ち寄ります。内部の全履歴や私的な対話、試行錯誤を明け渡す必要はありません。

協働全体を外に対する一つの思考体として扱い、開口部だけで関わる。これが、ここでいう **Supernode** の考え方です。外へ渡すものには、誰の提案か、どこまで合意したか、どんな違いが残るかを添えます。

### 戦わせるのは、中庭で形にした提案

意見が衝突したら、それぞれの場で考えた提案・成果物・根拠を中庭へ置き、その内容を検討します。人の人格や内面を評価する場にせず、どの条件が違い、何を変えると前へ進めるかを問い合います。

違いを勝敗や多数決で消す必要はありません。別案、保留理由、次に確かめたいことも、そのまま残せます。生身の人間が直接対立を引き受け続けずに済むよう、静的データを対話の足場にします。

## 一つの中庭を開く

このリポジトリは、自律分散の協働プロトコルを文書で定めた、テンプレート兼仕様モックです。

```sh
git clone https://github.com/kentaroid-bot/dokodemo-mesh.git my-courtyard
cd my-courtyard
```

GitHubの「Use this template」やファイルのコピーでも始められます。実務の中庭は、参加者に合った公開範囲で作ってください。この配布用リポジトリへ実務の記録を書き戻す必要はありません。

1. **集まる理由を書く。** [purpose.md](purpose.md)に、何を育て、何を持ち帰るかを書く。
2. **参加者と場所を揃える。** [desks.md](desks.md)に窓口、共有先、保存を担う人、持ち帰る方法を書く。
3. **最初の約束を合意する。** [agreements.md](agreements.md)の初期案を各デスクで検討し、全員の返答を残す。未合意の間は準備中として扱う。
4. **一つの問いを置く。** `work/template-task/` を `work/相談の名前/` へコピーし、`TASK.md` を埋める。

### 巡回と対話の往復

**中庭を読む → 自分のデスクへ持ち帰る → 人やAIと検討する → 回答や成果を中庭へ返す。**

各巡回係は、自分のデスクから任された範囲で動きます。人間は普段の仕事場で相談・判断・試行に参加でき、中庭へ直接書いてもかまいません。同じAIが複数のデスクを担当する場合も、それぞれの立場と返答を分けます。

「持ち帰った」「引き受けた」「合意した」は別の状態です。沈黙を同意に変えず、次に誰の何を待つかを残します。

ファイルを置くだけでは巡回は始まりません。まずは「この中庭を読んで」と頼むだけでも使えます。定期巡回は、各デスクの実行環境で担当・頻度・権限を設定します。

## 中庭に置くもの

| ファイル | 役割 |
|---|---|
| [purpose.md](purpose.md) | 集まる理由、それぞれが得たいもの、終える目安 |
| [desks.md](desks.md) | 参加デスク、持ち寄るもの、窓口と共有先 |
| [agreements.md](agreements.md) | 巡回係の7つの約束、全員合意と改訂の手順 |
| [notes.md](notes.md) | 言い直し、分かったこと、残る違い、判断理由 |
| [work/template-task/TASK.md](work/template-task/TASK.md) | 問いから持ち帰り・検討・応答・成果までを辿る作業票 |

## 持ち帰って、閉じる

各デスクは、退出に全員の許可を求める必要はありません。共通ルールを変える合意と、参加を終える自由は別です。

- 成果と必要な理由を各デスクへ保存し直し、中庭へのリンクだけに頼らず使えるようにする。
- 残る仕事は、引き取る先や保留理由を記す。引受け先がないことを退出の禁止理由にしない。
- 巡回を止め、合意済みの保管・削除方法で共有フォルダを片づける。

一人の退出で他の参加者の共有物を無断で消すことはありません。残る参加者は、成立要件を保つ範囲で続けられます。中庭全体を閉じるときも、最初に決めた終了手順で成果を持ち帰り、更地に戻せます。

## 約束を実際に支えるもの

GitHubや共有フォルダには、技術上の所有者や管理権限があります。**保存場所の管理者を、共同のルールを決める所有者にしない。** 管理範囲を公開し、全員が合意した成果を随時持ち帰れ、別の場所へ移れる状態を作ります。それを確保できない場は、この仕様のメッシュとして扱いません。

この文書は参加者が守る約束であり、アクセス制御や自動同期を実装するソフトウェアではありません。管理権限の濫用、情報の再共有、対話での傷つきを自動的に防ぐ保証もありません。共有済みのコピーやGit履歴は、閉じるだけでは消えません。実際の保存先・権限・共有内容を、この約束に合わせて選びます。
