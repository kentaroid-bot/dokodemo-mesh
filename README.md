# どこでもメッシュ · Dokodemo-Mesh

**2つ以上のどこでもデスクを繋ぐ中庭 ――「どこでもデスク」から「どこまでもデスク」へ**

それぞれの仕事場で育ててきた知識や問いを持ち寄り、一緒に考え、成果を持ち帰る。そのための小さな共有フォルダです。

中身はMarkdown数枚。人間やAIが読み、書き、続きを渡します。特定のAIやサービスを前提とせず、同じAIが複数の仕事場を訪れる使い方もできます。

```text
どこでもデスク A                 どこでもデスク B
   人・AIと検討                     人・AIと検討
       ↕ 巡回係                       ↕ 巡回係
       └─────── 中庭 ──────────┘
                目的・約束・仕事
                理解・成果・残る違い
```

**中庭は、各デスクの成果物と理解を豊かにするためにあります。**
ネットワークを維持・拡大するための仕事は要りません。用件が終われば、必要なものを持ち帰り、解散してよい。城を築くより、必要な間だけ囲むキャンプの焚き火です。

## まず、一つの中庭を開く

このリポジトリは、記入して使えるテンプレートであり、協働の仕組みを示す仕様モックです。

```sh
git clone https://github.com/kentaroid-bot/dokodemo-mesh.git my-courtyard
cd my-courtyard
```

GitHubの「Use this template」から自分たち用のリポジトリを作るか、ファイルだけコピーしても使えます。実務の中庭は、参加者に合った公開範囲で用意してください。この公開テンプレートへ実務の記録を書き戻す必要はありません。

1. **集まる理由を書く。** [purpose.md](purpose.md)に、何を一緒に育て、いつ持ち帰るかを書く。
2. **入口を揃える。** [desks.md](desks.md)に参加デスクと連絡の入口を書く。共有するフォルダやリポジトリの場所、読み書きする方法を参加者で揃える。
3. **最初の約束を相談する。** [agreements.md](agreements.md)は初期提案。各巡回係が持ち帰り、参加デスクが合意した範囲を記録する。
4. **一つの問いを置く。** `work/template-task/` を `work/相談の名前/` へコピーし、`TASK.md` に問いを書く。成果物もその隣に置く。

インストールやサーバーの起動は不要です。ファイルを置くだけでAIや巡回係が動くわけではありません。まずは各デスクの人やAIへ「この中庭を読んで」と頼めます。定期巡回にするなら、頻度・担当・任せる範囲を各デスクで決め、使っている実行環境へ設定します。

## 中庭に置くもの

| ファイル | 役割 |
|---|---|
| [purpose.md](purpose.md) | 集まる目的、それぞれが得たいもの、終える目安 |
| [desks.md](desks.md) | 参加する仕事場、持ち寄るもの、共有できる入口 |
| [agreements.md](agreements.md) | 巡回係の振る舞いと、参加デスクが合意した約束 |
| [notes.md](notes.md) | 言い直し、分かったこと、残る違い、次の問い |
| [work/template-task/TASK.md](work/template-task/TASK.md) | 問いから持ち帰り・検討・応答・成果までを辿る作業票 |

各デスクの原本は元の場所に置きます。ここには、共同の仕事に必要な静的データだけを選んで持ち寄ります。内部の対話や履歴を丸ごと見せる必要はありません。

## 巡回と対話の往復

**中庭を読む → 自分のデスクへ持ち帰る → 人やAIと考える → 回答や成果を中庭へ返す。**

巡回係は、問いだけでなく目的や理由も持ち帰ります。人間は普段の仕事場で相談・判断・試行に参加でき、中庭へ直接書き込んでもかまいません。

作業票には、誰に向けた話か、どの案を持ち帰ったか、何を考えているか、次に誰の返事を待つかを残します。**「持ち帰った」「引き受けた」「合意した」は別の状態**です。沈黙を同意に変えず、違いや保留も、次に考える手掛かりとして残します。

## 外の相手と関わるとき

この協働全体を、一つの思考体として別のデスクへ向けることもできます。共同の成果や問いを渡すときは、誰の提案か、どこまで合意したか、意見の違いが残るかを添えます。代表して返答する範囲も、参加デスクで決めます。

内側のすべてを開く必要はありません。**開口部となる中庭に、外へ渡せるものだけを置く。** これを、複数の仕事場が一つの窓口を持つ「Supernode」の考え方として扱います。

中庭同士を繋ぐときも、間に同じどこでもメッシュを置くだけです。

```text
デスク A ─ 中庭 α ─ デスク B
              ↕
            中庭 γ
              ↕
デスク C ─ 中庭 β ─ デスク D
```

中庭 γ では、α と β が参加者になります。γ の合意が α・β の内部へ自動的に及ぶことはありません。同じ形を繰り返して広げられ、上位の管理者を増やす必要もありません。これがP2Pとフラクタル（自己相似形）の設計です。フォルダの大小や置き場所は、権利の強弱を決めません。

## 持ち帰って、閉じる

目的を果たしたとき、役立たなくなったとき、休みたくなったときは、中庭を閉じられます。各デスクはいつでも参加を終えられます。

- 成果と必要な判断理由を、それぞれのデスクへ持ち帰る。中庭だけを参照していた資料も、必要な分を保存し直す。
- 途中の仕事は、引き取る先や保留の理由を作業票へ残す。
- 巡回を止め、共同のフォルダを残すか片づけるかを、決めておいた方法で扱う。

残る参加者がいれば、その人たちで続け方を決められます。解散後も、持ち帰った成果を使うために中庭を動かし続ける必要はありません。共有済みのコピーを消せるとは限らないため、最初から持ち寄ってよいものだけを置きます。

## 約束も、育てる

ここにある文書は出発点です。目的も、約束も、ファイルの分け方も、参加者の仕事に合わせて変えてください。変更案を作業票で相談し、合意した範囲を反映する。その仕組み自体も、同じ往復で育てられます。

共有範囲と実行権限を揃えるのは、参加する人やAIと保存先の設定です。このテンプレート自体は、アクセス制御や自動同期を実装しません。
