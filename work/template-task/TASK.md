## 持ち帰りと返答

宛先ごとに記す。状態は一列に進む達成段階ではなく、今の関わり方を表す。合意後に新しい問いや保留へ戻ってもよい。中庭の案は各デスクへの直接の命令ではない。各自のデスクへ持ち帰り、そのデスク固有の目的（`purpose.md`）や判断軸に照らして独立に検討した結果を返す。

| どこでもデスク・中庭 | 持ち帰った内容・日時 | 検討状況・返答（持ち帰り／検討中／提案／合意／保留） | 次の動き・内部作業参照（任意） |
|---|---|---|---|
| （記入） | （案の版と日時） | （状態、返答者、理由、合意する範囲。未応答は未応答のまま） | （次の動き。自デスクの作業ID等があれば記す。非公開パスは晒さない） |

| 状態 | 意味 |
|---|---|
| 持ち帰り | 自分の仕事場へ伝えた。引受けや合意ではない |
| 検討中 | 必要な人やAIと考えている |
| 提案 | 検討してほしい案を返した |
| 合意 | 指定した案の、記した範囲に同意した |
| 保留 | 今は決めない。違い・理由・再び考える条件を残す |

引き受ける場合は、担当・作業範囲・次の行動も明記する。各デスクで引き受けた実作業はそれぞれのデスク内の作業票を原本とし、同じ進捗を二重管理しない。合意だけで実作業の引受けを推定しない。相手の返答を自分の合意として代筆せず、沈黙を同意と扱わない。

約束の変更を扱う仕事なら、同じ変更案について参加デスク全員の明示的な合意を確認して [agreements.md](../../agreements.md) へ反映し、この作業票を理由の参照先として残す。

未応答・保留・反対があれば、約束の改訂は行わない。案を変更したら改めて全員の返答を揃える。一部のデスクだけで新しい進め方を試したい場合は、全体の約束を変えずにこの作業票の範囲内で試すか、必要なデスク同士で別の中庭（Fork）を開く。参加者の変更は本人の意思を確認し、反対者を除いて合意したことにしない。
